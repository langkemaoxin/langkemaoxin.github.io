读 Docker 网络前要懂的 IP、网段与网关

Linux 板块 · 第 2 篇
上一篇：《nsenter 前置知识》
下一篇：《tcpdump 抓包入门》（本文之后的排障与验证，都要靠它把包拍给你看）

开头：Docker 输出里跳出来一串数字

读 Docker 网络时，你会看到类似：

Subnet=172.17.0.0/16 Gateway=172.17.0.1

以及容器 IP：172.17.0.5。

很多人卡在「地址池」「/16」「网关」这几个词——不是 Docker 太难，是 IP 常识缺了一小块。本文只补这一块：读懂上面三行，再回去看 Docker 就不会懵。

目标：能用人话解释 Subnet / Gateway / 容器 IP 的关系，说清 /16 这种写法的含义，并回答两个方向的访问问题——为什么外人不能直接访问容器 IP，容器却能上网。
实验环境：WSL2 Ubuntu-22.04，内装原生 Docker Engine 29.1.3（非 Docker Desktop）；下文 docker0、路由、容器内输出均来自该环境。你的机器上具体号码几乎必然不同（比如容器是 .2 还是 .5），网段结构一致即可对照。

一、IP 地址：一张「网络门牌号」

是什么：IPv4 地址写成四段 0~255 的数字，如 172.17.0.5，用来在网络里标识一台设备上的一张网卡。

为什么：没有门牌号，包就不知道送给谁。发件人写自己的号（源 IP）、收件人写对方的号（目的 IP），网络才知道怎么投递。

怎么做（本机看一眼）：

$ ip -4 addr show docker0
6: docker0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default
    inet 172.17.0.1/16 brd 172.17.255.255 scope global docker0
       valid_lft forever preferred_lft forever

逐段读这一行：

片段含义
docker0网卡名。Docker 装好后自带的虚拟网卡，是所有容器的「总机」
inet 172.17.0.1/16这张网卡的 IPv4 门牌是 172.17.0.1；/16 第三节讲
brd 172.17.255.255这个网段的广播地址（3.3 节讲，先记个眼熟）
scope global全局有效：可以和本机之外的设备通信

背景知识：IP 属于网卡，不属于整机。一台机器可以有多张网卡、各领各的号；同一张网卡甚至可以挂多个 IP。再看一块「每台机器都有」的环回口：

$ ip -4 addr show lo
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever

lo 的 127.0.0.1 就是常说的 localhost——注意它的 scope 是 host（只在本机内部转，不出网卡）。你以后在服务器上看到「服务监听 127.0.0.1 所以外部连不上」，根子就在这。

二、私有地址：内网号，不是公网号

是什么：互联网上真正能全球路由的公网地址在 2026 年的今天是稀缺资源；家里、公司、云内网、Docker 默认用的，是 私有地址（RFC 1918 划定的保留段），共三类：

私有网段大小常见场景
10.0.0.0/8超大大企业内网、部分 K8s/云 VPC
172.16.0.0/12（含 172.17.x.x）大Docker 默认 bridge 常用
192.168.0.0/16中家庭路由器、办公室 LAN

为什么：IPv4 只有约 43 亿个号，全球设备远超这个数。办法就是：内网随便用私有号，出门时由网关做 NAT（网络地址转换）——把包的源地址改写成网关自己的出口地址，回来再把数据还给你。于是一整个内网可以共享少量甚至一个公网号。

这不是 Docker 的发明，你此刻就活在私有网段里——看本机 WSL 自己的物理侧网卡：

$ ip -4 addr show eth0
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    inet 172.22.212.111/20 brd 172.22.223.255 scope global eth0
       valid_lft forever preferred_lft forever

WSL 的 eth0 拿的是 172.22.212.111——一个 172.16.0.0/12 范围内的私有号，由 Windows 宿主分配。也就是说：WSL 是 Windows「内网」里的一台机器，Docker 容器又是 WSL 内网里的机器，一层套一层。

和 Docker 的关系：容器拿到的 172.17.0.5 是引擎内部的内网号，外面的公网、甚至你办公室另一台电脑，通常不能直接用这个号访问容器——所以才需要 -p 端口映射「开一扇门」。反方向（容器→外网）能通，靠的正是上面说的 NAT，第四节实测给你看。

三、网段与 /16：一排连续的号码

3.1 先从见过的 /24 说起

把 IP 想成「小区 + 门牌」：

  • 网段（subnet）：哪一片小区（号码范围）
  • 具体 IP：小区里的某一户

家里路由器最常见的网段是 192.168.1.0/24：前三段固定是 192.168.1，只有最后一段从 0 变到 255——共 256 个号的一小片小区。你家手机、电脑、电视都从这里领号。

3.2 /n 到底是什么：网络部分有 n 个二进制位

IP 地址本质是 32 个二进制位，四段数字只是方便人读（每段 8 位）。写成 网段/n（CIDR 记法）意思是一个约定：

前 n 位是「小区名」（网络部分），必须一模一样；剩下的位是「门牌」（主机部分），可以随便变。

不用真做二进制运算，记住换算关系就够：

写法固定部分可变部分范围（以 172.17 开头为例）号码总数
/24前三段（24 位）最后一段172.17.0.0 ~ 172.17.0.255256
/20前 20 位（两段 + 第三段的高 4 位）12 位172.17.208.0 ~ 172.17.223.2554096
/16前两段（16 位）后两段172.17.0.0 ~ 172.17.255.25565536

所以 172.17.0.0/16 读作：前两段固定 172.17，后两段可变——6.5 万多个号的一大片。/ 后面的数字越大，网段越小（小区越挤）。

表里 /20 那行的「第三段的高 4 位」展开看一眼就懂。每段是 8 个二进制位，左边叫高位、右边叫低位（和十进制「十位在前、个位在后」同理）；/20 = 前 16 位（两段全部）+ 第三段的左半边 4 位。拿 212 开刀：

212  =  1  1  0  1 │ 0  1  0  0
       └──高 4 位──┘ └──低 4 位──┘
        1101 被钉死    0100 可变

第三段高 4 位是 1101 的数，从 1101 0000（208）排到 1101 1111（223）共 16 个；到 1110 0000（224）高 4 位就变了、出了这片网段。所以 /20 的切法是：在 /16 的基础上，把第三段按「左半边」再锁一次——16 个第三段值 × 256 个第四段 = 4096 个号。

加餐：用这个方法读懂你自己机器。第二节里 WSL 的 eth0 是 172.22.212.111/20：前 20 位固定，即前两段 172.22 固定、第三段的高 4 位固定（212 与 208~223 共享高 4 位 1101），所以这片网段是 172.22.208.0 ~ 172.22.223.255——对照输出里的 brd 172.22.223.255（网段最后一个号），正好对上。

再进一步：网段可以套网段（长前缀套在短前缀里）。把 172.22.212.111 展开成二进制，看它同时属于谁：

172    . 22    . 212   . 111
10101100 00010110 11010100 01101111
└───前 16 位───┘└高4位┘
  • 属不属于 172.22.0.0/16？——只查前 16 位：10101100 00010110，正是 172.22 ✅
  • 属不属于 172.22.208.0/20？——多查 4 位：212（11010100）的高 4 位 1101，与 208~223 一致 ✅

规律一句话：/n 只检查前 n 位；n 越大检查越严，圈子越小。于是 172.22.208.0/20（前 20 位固定）的每个成员必然满足 172.22.0.0/16（只要求前 16 位）——小圈完全装在大圈里，如同「海淀区居民」都算「北京居民」。往后读 Docker 时会碰到它的直接应用：Docker 发网段前判断「候选段会不会和宿主网段相撞」，用的就是这套前缀包含/重叠检查。

3.3 两个不能分配给设备的号

每个网段里，有两个号是「公共设施」，不发给任何设备：

  • 网络地址（主机部分全 0，如 172.17.0.0）：代表「这片小区本身」。docker network inspect 里的 Subnet=172.17.0.0/16 用的就是它——它是在指认小区，不是某个设备的门牌
  • 广播地址（主机部分全 1，如 172.17.255.255）：发给它 = 喊给全小区听。第一节输出里的 brd 172.17.255.255 就是它在 ip addr 里的露面

3.4 「地址池」是什么？

Docker 说 Subnet = 地址池，意思就是：

这片网段里的号码，被保留给「挂在这张 Docker 网络上的容器」来分配。
新容器起来，就从池子里领一个还没人用的号（如 172.17.0.2、.3、.5…）。

类比：公司 IT 划了 172.17.* 给容器工位用——地址池 = 这批可分配的工位号，网络地址和广播地址是「机房」和「大喇叭」，不发人。

四、网关：出小区的那扇门

是什么：默认网关是「离开本网段、去别的地方」时，包先交给谁。它自己也是网段里的一个号，只是承担了「转发」的角色。

为什么：同网段设备可以直接对话（喊一嗓子全楼都听得见的范围内）；跨网段（访问公网、去别的网段）中间要有人转发——网关就干这个。没配网关的设备，只能在小范围里活动。

怎么做（进容器实测）：

$ docker run --rm busybox ip route
default via 172.17.0.1 dev eth0
172.17.0.0/16 dev eth0 scope link  src 172.17.0.5

第二行是「本网段内部直连」（scope link）；第一行 default via 172.17.0.1 就是默认网关——其余所有目的地，一律先把包交给 172.17.0.1，正是宿主机上的 docker0。

容器里 ping 一下网关，确认这扇门开着（0.07 毫秒，几乎零成本）：

$ docker run --rm busybox ping -c 2 172.17.0.1
PING 172.17.0.1 (172.17.0.1): 56 data bytes
64 bytes from 172.17.0.1: seq=0 ttl=64 time=0.077 ms
64 bytes from 172.17.0.1: seq=1 ttl=64 time=0.065 ms

--- 172.17.0.1 ping statistics ---
2 packets transmitted, 2 packets received, 0% packet loss
round-trip min/avg/max = 0.065/0.071/0.077 ms

再测「出了这扇门能不能到公网」——ping 一个公网 DNS（阿里 223.5.5.5）：

$ docker run --rm busybox ping -c 2 223.5.5.5
PING 223.5.5.5 (223.5.5.5): 56 data bytes
64 bytes from 223.5.5.5: seq=0 ttl=113 time=5.543 ms
64 bytes from 223.5.5.5: seq=1 ttl=113 time=5.793 ms

--- 223.5.5.5 ping statistics ---
2 packets transmitted, 2 packets received, 0% packet loss
round-trip min/avg/max = 5.543/5.668/5.793 ms

通了。容器手里的可是私有地址，包怎么出去的？——交给网关 172.17.0.1 之后，宿主机一路 NAT 改写源地址，一层层送出去；回程再原路改回来。把整条链画出来，你会发现「网关」是嵌套的：

每层的逻辑一模一样：我在某网段里，出网段就交给本段网关；网关们层层接力 + NAT。看懂这一层，Docker 网络的「容器为什么能上网、为什么外网进不来」就同时有了答案——出方向是网关+NAT 主动送出去的，进方向没人帮你转，所以得用 -p 在宿主机上开一扇显式的门。

五、三行 Docker 输出对照读

在引擎里执行：

$ docker network inspect bridge --format \
  'Subnet={{(index .IPAM.Config 0).Subnet}} Gateway={{(index .IPAM.Config 0).Gateway}}'
Subnet=172.17.0.0/16 Gateway=172.17.0.1

再看宿主机路由表里 docker0 那条：

$ ip -4 route | grep docker0
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1

含义：目的地是 172.17.0.0/16 这片小区的包，直接从 docker0 这张网卡送出去（proto kernel 表示内核起网卡时自动配的），本机在这片小区里的号是 172.17.0.1。容器那侧（第四节实测）则是镜像的另一半：172.17.0.0/16 dev eth0 scope link src 172.17.0.5。

再抓一个刚起的容器看它领到的号：

$ docker run --rm busybox ip -4 addr show eth0
2: eth0@if88: <BROADCAST,MULTICAST,UP,LOWER_UP,M-DOWN> mtu 1500 qdisc noqueue
    inet 172.17.0.5/16 brd 172.17.255.255 scope global eth0
       valid_lft forever preferred_lft forever

合并理解：

Subnet  172.17.0.0/16  →  地址池（可分配的号段；.0 是网络地址，.255.255 是广播地址）
Gateway 172.17.0.1     →  池子的门 / docker0 的门牌
容器 IP 172.17.0.5     →  从池子领到的一个号（你机器上是 .2/.3/... 都正常）

串起来：

Docker 在宿主机上划了一片私有网段当地址池；docker0 占网关号；每个新容器从池里领 IP，并把默认路由指到网关——于是容器既能跟同网段其它容器说话，又能经网关 + NAT 出网；而外人要进来，得靠宿主机上显式开的 -p 端口门。

顺带一眼：容器里这张网卡叫 eth0@if88——@if88 暗示它是一对虚拟网线（veth）的一端，另一头插在宿主机侧。这根线怎么接、网桥怎么转，正是 Docker 第 11 篇的正菜，本文不展开。

六、和 Docker 第 11 篇怎么衔接

读 《Docker 网络模式与实操》 时：

  1. 看见 Subnet / Gateway → 回想本文「地址池 + 门」
  2. 看见容器 172.17.0.x → 「池子里的一户」，不是公网 IP
  3. 看见 -p 18080:80 → 因为外人进不来这片私有池，所以要在宿主机开端口门
  4. 看见 eth0@if88、veth → 一对虚拟网线的两端，Docker 网络的物理底座

更深的东西不必直接跳 Docker 系列——本板块已经铺好进阶路：第 3 篇 tcpdump 把包拍给你看，第 4 篇 NAT 拆「换头术」，第 5 篇 netns/veth/iptables 手搓容器网络的两块地基（上面那个 @if88 的谜底就在那篇）。顺完这条线再进 Docker 第 11 篇最稳；本文只保证数字读得懂。

小结

  • IP：网络门牌号，属于网卡不属于整机；127.0.0.1（scope host）只在本机内转。
  • 私有地址：RFC 1918 三段内网号；出门靠网关 NAT 改写源地址——你的 WSL、Docker 容器此刻都活在内网号里。
  • 网段 /n：前 n 位是网络部分必须相同；/24 256 个号、/16 6.5 万个号；网段的 .0（网络地址）与末尾全 1（广播地址）不分配给设备。
  • 地址池：Docker 从该网段里给容器分 IP。
  • 网关：出网段先交给它；容器 default via 172.17.0.1 指向 docker0，宿主机 NAT 后出网——容器能上网而外网进不来，是同一个机制的两面。

思考题

若 docker network inspect 显示 Subnet=172.21.0.0/16、Gateway=172.21.0.1（自定义 bridge），容器 IP 却是 172.21.0.3，这和默认 172.17.0.0/16 是同一片地址池吗？应用里该写死这个 IP，还是写容器名？

再加一问：这个网段里 172.21.0.0 和 172.21.255.255 会被分配给容器吗？

（提示：不同 Docker 网络可以有各自的地址池；名字解析见 Docker 第 11 篇自定义 bridge；两个特殊号见本文 3.3 节。）
