## 一、本文要解决的问题

同一个模型，为什么换个问法结果天差地别？system、few-shot、CoT 各自改变模型的什么行为？prompt 工程不是玄学咒语，是给一个无状态函数设计输入。

## 二、知识点清单

- system / user / assistant 三种消息的职责分工
- few-shot：用示例定义任务，常比文字描述更有效
- CoT：让模型先写推理过程再给答案——什么时候有效、什么时候白费 token
- prompt 的「接口设计」视角：输入约束、输出格式、失败示例

## 三、动手实验（学习时必须真跑）

- 同一任务三种写法（只指令 / 加 few-shot / 加 CoT）各跑 20 次，统计成功率
- 故意写一个歧义 prompt，观察模型理解偏到哪去了

## 四、验收标准（全部通过才进入下一篇）

- [ ] 能说清每种手法「改变的是模型的哪部分行为」，有自己的成功率对照表
