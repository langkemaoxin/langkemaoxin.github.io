# 第 13 站：有效权限

前面第 [9](./10-ace-dacl.md)、[10](./11-access-check.md)、[12](./13-inheritance.md) 站，小王已经会：门上贴 ACE、令牌对表、继承往下传。  
本站用**一则案例**回答他改完权限后最常问的一句：

> 规则叠了这么多行——**这个人，对这个文件，到底能不能动？**

专有名词后置；有效权限**不是**第三种 ACL。

---

### 故事：门上写了十几行，小王算不清小李能不能开

#### 场景

项目目录经过几轮调整，深层文件长这样：

```text
E:\协同\项目A\图纸\总平.dwg
```

小王用 `icacls` 一看，DACL 里既有：

- 从父目录**继承**下来的：项目组 `(RX)`、只读组 `(R)`；  
- 自己**显式**加的：给设总 `(F)`；  
- 还有一条历史遗留：对某个账户 **Deny** 写入。

同事小李说：「我打不开总平。」  
小王盯着十几行 ACE，开始用手算：

> 他在项目组里……所以有 RX……  
> 但只读组也有他……  
> Deny 那条是不是针对别人？  
> 父目录和子文件继承标志又不一样……

算到一半，小王放弃了。

#### 小王的错误直觉

「把门上每一行 Allow/Deny 在脑子里加加减减，就能得出答案。」  
「或者只看父文件夹权限，子文件应该一样。」

#### 一起推导

1. [第 10 站](./11-access-check.md) 已经发明过：打开文件时，系统拿**令牌里的 SID（含组）**去对**这扇门的 DACL**。  
2. 人脑难的地方在于：组嵌套、显式/继承混用、Deny 与 Allow 冲突、深层对象上的 ACE 集合 ≠ 父目录那一张表。  
3. 所以需要一个东西：**不要新发明一种权限**，而是把「对表结果」用界面或工具显示出来——回答的是「**对这个用户/组，有效结果如何**」。

#### 现在才起学名

| 故事里的东西 | 官方常叫 |
|--------------|----------|
| 「算完之后，他到底能不能怎样」 | **有效权限 / 有效访问（Effective Access）** |
| 门上那一堆行 | 仍是 **DACL 里的 ACE**（没有第三张表） |

> 有效权限 = **访问检查的求值结果（可视化）**，不是又一种可以单独「授予」的权限类型。

资源管理器里：文件/文件夹 → 属性 → 安全 → 高级 → **有效访问**（Effective Access）选项卡，选一个用户或组，查看系统估算的结果。  
（界面文案随 Windows 版本略有差异，找「有效访问 / Effective Access」即可。）

来源（权限与 Deny 通常压过 Allow 的模型）：[Appendix B - Privileged accounts（Permissions）](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/plan/security-best-practices/appendix-b--privileged-accounts-and-groups-in-active-directory)  
安全描述符含 DACL/SACL 的总述：[Understand security principals](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-principals)

### 小王怎么「看见」：两条路，别混成一条

#### 路 A：看门上写了什么（规则列表）

```bat
icacls E:\协同\项目A\图纸\总平.dwg
```

或：

```powershell
Get-Acl E:\协同\项目A\图纸\总平.dwg | Format-List
```

这回答的是：**DACL 里有哪些 ACE**（含继承来的）。  
它**不直接**打印「小李：可读=是，可写=否」这种一句话结论——那是人脑或「有效访问」要做的求值。

来源：[icacls](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)

#### 路 B：看对某个人的求值结果（有效访问）

```text
总平.dwg → 属性 → 安全 → 高级 → 有效访问
  → 选择用户：小李
  → 查看有效访问
```

这回答的是：**若用这个主体去对当前对象做访问检查，各项能力大致如何**。

小王记一句：

| 你想问 | 用哪条路 |
|--------|----------|
| 门上贴了哪些规矩？ | `icacls` / `Get-Acl` / 安全选项卡列表 |
| 某人最终能不能怎样？ | **有效访问**（再辅以真人登录试开） |

### 案例续集：三种「算不清」的现场

下面三个小场景，都建立在同一句话上：  
**先看有效访问，再回 DACL 找是哪一行导致的。**

#### 案例 1：Allow 很多行，仍打不开——Deny 赢了

门上：

- 项目组：允许读取；  
- 小李本人：显式 **Deny 读取**（误操作或临时封锁留下的）。

小李在项目组里，小王以为「在组里就能读」。  
有效访问：读取相关项为否 / 显示被拒绝。

推导（呼应第 9～10 站）：

> 对表时，**Deny 通常压过 Allow**。  
> 组给的 Allow 救不了「本人一条 Deny」。

处理直觉：先找 Deny 那一行是谁写的、还要不要；不要只顾再加一条 Allow。

#### 案例 2：父目录能进，深层文件不能——看的不是同一扇门

小李能打开 `E:\协同\项目A\`，打不开 `...\图纸\总平.dwg`。

小王只查了项目A 的有效访问，显示可读——以为「下面都一样」。

推导（呼应第 12 站）：

> 每个对象可以有**自己的** DACL；继承、IO/NP、中途切断继承，都会让子对象与父对象规则不同。  
> **有效访问必须针对「打不开的那一个对象」再查一次。**

#### 案例 3：本机有效访问说「能」，UNC 仍拒绝——还有第二道门

小王在文件服务器本机查：小李对某文件夹有效访问可读。  
小李从自己电脑用 `\\服务器\共享\...` 仍拒绝访问。

推导（呼应第 10 站）：

> 有效访问（资源管理器这一页）主要帮你看清 **NTFS 这一道门**的对表结果。  
> 走 UNC 时还有 **共享权限 ∩ NTFS**；共享侧过不去，本机 NTFS「有效能读」也救不了。

所以：UNC 不通时，有效访问说「能」≠ 网络路径一定能开——两道门都要查。

---

### 有效访问不是神仙：小王需要知道的边界

1. **它可视化的是授权求值，不替代真人试开。** 偶发策略、软件自身权限、打开方式不同，仍以实际打开为准。  
2. **选错主体就问错问题。** 要查小李，就选小李（或他当时所属的组场景）；选错成设总，结果再漂亮也没用。  
3. **进组刚变完，令牌可能还是旧的**（第 8、5 站）：有效访问按你选的账户算「应有成员」；小李若未重新登录，他电脑上的进程令牌可能还没带新组——会出现「工具说能、他那边不能」。  
4. **用户权利 / 备份特权等**（第 17 站）不在「普通打开文件」同一条路上；有效访问按普通访问检查理解即可，本站不把备份绕过画进来。  
5. **UAC**：管理员日常票与管理员票不同；「以谁的身份去问有效访问」要和真实打开文件的进程身份一致，否则会误判。

---

### 改完继承后的最小习惯（给小王的操作清单）

```text
1) 改 DACL / 继承（第 9、12 站）
2) icacls 或安全选项卡：确认「门上的字」符合预期
3) 对「会抱怨的那个人 + 打不开的那个对象」跑一次有效访问
4) 若走 UNC：再查共享权限（第 10 站）
5) 仍不符：问对方是否重新登录、进程是否提升（令牌 / UAC）
```

---

### 收束

**你现在会了：**  
有效权限 / 有效访问 = 把「令牌对 DACL」的结果显示出来，**不是**第三种权限；`icacls` 看规则列表，有效访问看对某人的求值；Deny、深层对象、共享第二道门、令牌未刷新，都会让「眼算」翻车。

**下一站才需要：** 如何记录「谁碰过」，而不只是「能不能碰」——那是 SACL / 审计。
