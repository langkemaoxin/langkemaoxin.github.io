## 一、本文要解决的问题

综合运用全部十阶段知识，交出一份能落地的完整设计——这是出师考试：不是每项技术都用最猛的，而是每个决定都有依据、每个组件都有代价清单、每个风险都有预案。

## 二、知识点清单

- 需求（给定）：日活 3000 万电商 + 站内 IM 客服；峰值交易 2 万 QPS、日消息 3 亿条；可用性 99.95%
- 八份交付物：容量估算 / 总体架构 / 数据库分片方案 / 缓存方案 / 消息方案 / 流量防护预案 / 高可用方案 / 压测与容量报告
- 强制要求：分片键论证、降级三级预案、堆积应急预案、容量数据可复算、每个选型含否决理由
- 最小可运行核心：下单（分片 + 缓存 + 削峰）+ IM 收发（推拉 + seq）两条链路真实跑通
- 压测验收：核心链路达到设计容量的 50% 以上（笔记本环境的合理折算）

## 三、动手实验（学习时必须真跑）

- 全链路压测并出报告：实测容量、瓶颈、优化记录
