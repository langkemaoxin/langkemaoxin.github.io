## 一、本文要解决的问题

限流熔断的道理都懂了，生产上还要解决工程问题：几十个服务几百条规则怎么统一管理？改规则要重启应用吗？控制台重启规则会丢吗？这一篇把 Sentinel 的规则体系与生产化落地（Nacos 持久化）整套搭通。

## 二、知识点清单

- Sentinel 架构：Slot 责任链（NodeSelector → ClusterBuilder → 统计 → 规则检查 → 异常），扩展点概览
- 五类规则：流控（QPS / 并发 / 关联 / 链路）、熔断降级、热点参数、系统规则、来源访问——每类解决什么问题
- 控制台：dashboard 部署、应用接入（客户端标记 + 传输），内存态规则的问题（重启丢失）
- 规则持久化：Nacos 数据源（推模式），规则生产链路「控制台改 → Nacos 存 → 应用监听生效」
- 整合网关限流：Spring Cloud Gateway + Sentinel 网关流控规则，入口层与服务层的双层防护

## 三、动手实验（学习时必须真跑）

- Spring Boot 应用接入 Sentinel + dashboard，配置 QPS 流控规则压测验证
- 接 Nacos 数据源做规则持久化：控制台改规则 → 重启应用验证规则还在 → 动态调整阈值热生效
- 热点参数限流实验：对「商品 id」维度限流，压同一 id 与随机 id 对比放行行为
