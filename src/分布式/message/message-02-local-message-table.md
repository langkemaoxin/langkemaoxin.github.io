## 一、本文要解决的问题

不依赖任何 MQ 特性，怎么保证「业务成功」和「消息必达」原子？先手写本地消息表，才能真懂后面框架帮你做了什么。

## 二、知识点清单

- 业务表 + outbox 消息表同库同事务插入（原子性的来源）
- 后台扫表补发 + 指数退避 + 已发标记
- 最少一次语义下的消费端幂等要求
- 扫描任务的分页、并发控制与性能影响

## 三、动手实验（学习时必须真跑）

- 手写本地消息表版「注册成功-发优惠券」：业务与 outbox 同事务写入，后台线程扫描补发
- kill 消费方再重启，验证消息最终送达（券不丢）
