## 一、本文要解决的问题

给你一个新系统，从哪里开始设计？「先画个架构图」是最常见的错误起点——正确顺序是先量化（容量估算）、再选型（逐个组件论证）、再画图（视图表达）、最后演进（预留变化）。这一篇把 24 周的知识收束成一套可复用的开工流程。

## 二、知识点清单

- 需求分析：功能需求之外的四个非功能维度——QPS / 延迟 / 可用性 / 一致性，每个都要量化成数字
- 量化先行：容量估算表（阶段 0 的方法）作为一切设计的输入
- 架构的四种视图：部署图（机器视角）、数据流图（请求视角）、依赖图（服务视角）、演进图（时间视角）
- 选型评估框架：成熟度 / 团队熟悉度 / 生态 / 成本四维打分，每个选型记录否决项
- 演进式架构：为变化设计（哪里最可能扩、哪里先简化），「够用就好」的判断力
- 架构评审清单：容量依据、单点、降级预案、数据一致性、成本——五问过堂

## 三、动手实验（学习时必须真跑）

- 拿「亿级消息推送平台」需求做完整推演：需求量化 → 容量估算 → 架构图（四视图）→ 选型表 → 演进路线
- 组织一次自我评审：用五问清单过堂自己的设计，记录每个被问倒的点并补齐
